Business Inference Tree

How it works

  • Runs entirely in your browser. The app's Python engine runs in Pyodide (Python compiled to WebAssembly). There is no server: uploaded data never leaves the page.
  • First visit: it downloads Python, numpy and pandas (about 15 MB, then cached). Startup takes 10–30 seconds.
  • Agnostic to the data. Click Upload CSV and use any file with a 0/1 target (1 = the event: default, fraud, churn, repayment…) and, ideally, a score column.
  • Saved trees and strategies are kept in this browser (localStorage). Send to Studio in the Tree Builder makes the strategy appear in Strategy Studio.
  • Written datasets (Write decisions dataset) are downloaded as CSV files.
  • Optimal splits use an exact dynamic-programming binning (IV-maximising, with minimum bin size and monotonic trend). The installed version can use the optbinning library instead.
  • Not in the demo: Visual ML model import, which needs a Dataiku project.

Try it in two minutes

  1. Open the Tree Builder. The sample is pre-selected, with target default_next_month and score behaviour_score. Click Load population.
  2. Click the top-ranked attribute (e.g. pay_status_m1) and then Apply split. Refine the bins in Bin statistics.
  3. Select the root → Logic → Default outputs: add apr = round(0.12 + 0.5 * leaf_event_rate, 4) and click Apply logic.
  4. On a leaf, set Decision = from an output… with credit_decision = 'APPROVE' if leaf_event_rate < 0.15 else 'DECLINE'.
  5. Set Holdout % = 30, click Freeze leaf rates, open Calibration…, then Download the SQL export.

Sample data

Default of Credit Card Clients: 30,000 credit-card customers in Taiwan (2005) with a default next month flag (22.1 % events). Yeh, I-C. & Lien, C-H. (2009), Expert Systems with Applications 36(2). UCI Machine Learning Repository, licensed CC BY 4.0.

Changes made for this demo:

  • readable column names; months labelled m1 (most recent) … m6;
  • sex, marital status and age removed;
  • education decoded to labels;
  • derived features added (utilisation, delinquency counts, payment ratio);
  • a 50/50 sample column (development / validation);
  • behaviour_score, a simple logistic scorecard fitted on the development half (600 points at 50:1 odds, 20 points to double the odds).

The script is demo/tools/prepare_uci_credit.py.

Demo only. The sample data and behaviour_score are for illustration and are not a validated credit model. Nothing here is financial, credit-risk or regulatory advice.
